# Expose one operation catalog with plan, apply, and receipt

Status: proposed, 18 September 2026; accepted when the pull request that adds it merges

tC Admin's Worker exposes its behavior as a catalog of named operations ([operations.md](../operations.md)). A read returns the complete situation of its subject in one response (the portfolio, a project, a release preparation) with the provenance and age of every derived fact. A mutation is two operations: a **plan**, which computes exactly what would be written to Door43 without writing anything and is bound to the source commit it was computed from; and an **apply**, which takes the plan, re-checks the binding and the permission, performs only the writes the plan listed, and returns a **receipt** naming what it wrote. Every failure is a code from one error catalog with the user message the specification fixes, whether it is retryable, and the next action.

The browser UI is one projection of the catalog: each wizard and stepper step calls one operation. A later MCP server for Claude clients is another projection, one tool per operation with the same schemas and the same plan-before-apply rule, so an agent operating tC Admin follows the same safety path a manager does. Tests exercise operations directly against recorded fixtures (ADR 0012). Operation names, state values, error codes, and project type and format values are the identifiers listed in [CONTEXT.md](../../CONTEXT.md), spelled the same in code, API, tests, logs, and documents.

The manager's safety rules (review before commit, restart when the source moves, never duplicate a release, never write outside the announced set) are the same rules an agent needs, and plan/apply/receipt makes them structural rather than re-implemented screen by screen. One catalog keeps the Worker, the web client, the tests, and the documents in one vocabulary, which is what lets one part-time engineer with agent assistance build and verify the system in the time available. The cost is ceremony for small reads, which stay plain reads, and the discipline of defining the shared schema before the first route.

Consequences: the application foundation ([#7](https://github.com/unfoldingWord-box3/tc-admin-app/issues/7)) creates the shared schema package before the UI; every Milestone 1 issue names the operations it implements; the roadmap's deferred MCP server becomes a thin projection rather than new work.
